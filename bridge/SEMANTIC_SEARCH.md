# 数据总览：本地语义检索

版本 0.34.0。为帖子数据库和评论数据库提供 RAG 的检索层：自然语言召回、主题重排、原文证据溯源。当前不生成概括性答案，也不自动改写已有情绪标签。

## 使用

1. 在数据总览选择帖子或评论数据库，完成原有一致性校验。
2. 开启「语义检索」，输入描述，或点「差评 / 强硬销售 / 价格差异 / 过敏」。
3. 点击「搜索」或按 Enter。编辑输入时不会自动反复调用向量模型。
4. 结果按相关度排列，显示原文证据、证据评论 ID 和历史删除状态。帖子结果会同时检索帖子正文及所属评论。
5. 原有字段筛选仍然有效。语义模式暂时暂停手动排序和楼层合并，关闭后恢复偏好。

默认取综合相关度不低于 0.50 的前 200 条。相关度不是百分比置信度，也不意味着已证实差评、强迫销售或产品致敏。存在已删除的历史评论时会明确标注。自然语言检索可能召回否定、转述、其他品牌和商家回复，请结合原文判断；要求仅查看已标注差评时，可叠加原有「分析结论是否差评」或人工负面筛选。

## 模型与运行方式

- 使用 [BAAI/bge-small-zh-v1.5](https://huggingface.co/BAAI/bge-small-zh-v1.5)，固定修订 `7999e1d3359715c523056ef9478215996d62a620`。
- CLS pooling、L2 归一化、查询加模型推荐检索指令。长文按 360 字分块，60 字重叠，避免仅编码开头。
- 「差评」使用多个投诉主题的最大 cosine 召回。四个快捷主题对已有正面标注适度降权；差评模式对已有负面标注加权、中性标注降权。保留原始 cosine 与重排说明，检索过程不产生新的情绪判定。
- 未知标签不作负面推断。快捷「过敏 / 差评」会降低明确“之前其他产品过敏、当前体验良好”对比句的权重，并排除简单、无转折且无其他风险描述的“没有过敏”句；这不是完整的否定或品牌归属识别器。
- 文件及内容仅在本地处理，不向 DeepSeek 或其他云服务发送评论，不消耗云 API 额度。
- Native Host 不打包 Torch，使用独立、隐藏的 Python 子进程运行模型；只通过管道通信，不开放额外端口。
- 模型权重约 96 MB，首次索引需要等待。每批完成即缓存，后续查询复用向量；模型修订和原文变化会改变缓存键。
- 索引是业务 DB 旁的 `*.semantic.sqlite3` 派生缓存，不修改业务 SQLite、CSV、素材或已有标签。每次从当前一致性快照获得候选 ID，删除或筛选掉的记录不会从旧缓存复活。

## 安装与恢复

使用同一个 Python 执行以下命令（在 bridge 目录中）：

```powershell
python -m pip install -r requirements-semantic.txt
python setup_semantic.py
```

首次安装下载公开模型文件，之后运行启用 `HF_HUB_OFFLINE` / `TRANSFORMERS_OFFLINE`。安装器记录本机 Python 路径至 `semantic_runtime.json`。若迁移电脑或删除该 Python 环境，重新执行安装。未安装或模型损坏时明确报错，不冒充语义检索退化成关键词搜索。

重新编译 Native Host 后升级已注册的 executable，随后在浏览器扩展管理页重新加载插件。模型目录、运行时路径和向量缓存均在版本控制之外。

API 沿用 `queryDataOverview`，新增 `semanticSearch: true`，可设置 `semanticMinScore`（0–1，默认 0.5）和 `semanticLimit`（1–2000，默认 200）。先执行原有筛选，再检索全部合格分块，按记录去重、重排和分页。响应里的 `total` 是限制后的命中数，不是数据库总量。

## 测试

```powershell
python -B -m unittest discover -s bridge -p test_semantic_search.py -v
```

测试仅使用临时数据和确定性编码器，覆盖快照门禁、候选范围、先筛后排、分页、原文分块、普通搜索回归、SQL 参数化、只读、已有标签重排、否定句及历史评论标注。真实模型质量和浏览器交互另做验收，不能由 mock 测试代替。
